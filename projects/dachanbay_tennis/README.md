# 昀湾文体中心网球预约

Windows / macOS 本机运行，安装步骤见仓库根目录 README。默认目标为周二 21:00–22:00、周三 19:00–20:00，任意网球场。
通过接口自动提交预约，付款由本人完成。项目复用公共加密、进程互斥和系统适配层，图形界面使用 Tkinter。

## 运行

仓库根目录执行，或双击本目录 `launch.cmd`（Windows）/ `launch.command`（macOS），优先使用仓库 `.venv`：

```powershell
python -m projects.dachanbay_tennis watch
python -m projects.dachanbay_tennis query
python -m projects.dachanbay_tennis capture-payment
python -m projects.dachanbay_tennis capture-login --timeout 300
python -m projects.dachanbay_tennis plan
python -m projects.dachanbay_tennis check-cashier
```

`watch` 和 `capture` 均打开接口助手，不会自动开始下单；`query` 使用已保存凭证，只做查询。
安装仓库后也可以运行 `book-ticket-tennis`。

## 自动预约并交接微信收银台

Windows 可使用“自动采集并恢复代理”，或运行 `capture-login`：采集开始后在电脑微信重新打开 HTTP 网站，
进入网球场并切换日期。程序只接受校验通过的登录态，并在成功、超时或正常中断时恢复原代理。
异常退出留下加密恢复记录时，运行 `python -m projects.dachanbay_tennis recover-proxy`。
若代理已被其他程序修改，工具保留记录并要求人工恢复，不覆盖新设置。

先运行 `plan`，阅读实时须知，使用其输出的 SHA256 明确确认本次协议：

```powershell
# 协议摘要替换成 plan 输出的实际值；明确接受服务器返回的任意价格。
python -m projects.dachanbay_tennis book --approve-notice 实际SHA256 --unlimited-price
# 也可以限定单小时金额：--max-price 60
```

临时试订某一天可用的一小时付费场次时，使用 `plan --date YYYY-MM-DD --paid-only` 预览，
再运行 `book --date YYYY-MM-DD --paid-only --approve-notice 实际SHA256 --unlimited-price`。
只查询并提交指定日期的一个可用场次，不修改周二/周三的每日守候目标；日期尚未开放或没有可用场次时不提交。
`book` 在一次性页面中重新校验微信登录，不依赖旧凭证仍有效。运行单次试订前先用 `stop-daily` 停止后台守候，
完成后再按原参数启动 `daily`。

程序校验当前官网前端版本，启动临时 HTTP 代理并输出一次性链接。**在电脑微信打开该链接并保持页面打开**，
页面用微信原有登录态完成握手后，程序才会复核条件并提交一次预约。
付费场次显示日期、时段和报价，由本人点击“继续付款”后调用官网收银台；轮询不会自动拉起付款。
付款按钮仅接受一次点击，过期后不会继续调用 SDK 或重订。
最终金额、密码及付款确认由本人在微信操作。无需 F12、复制 Token 或安装证书。
本工具不能代替微信登录授权；接口和离线测试通过也不能证明真实收银台能够付款。

收银台交接按同一登录态、一次性随机链接和同源请求校验，签名支付参数只在内存中短暂传递，
响应只领取一次；结果不明不重放、不重订。官网版本变化时在下单前停止。
“收银台调用已发起”只表示官方 SDK 调用已返回，不表示付款页已打开或已支付。
关闭收银台不会由助手自动取消订单。官网订单列表未验证存在待支付补付入口，交接失败应核对订单或联系场馆。

macOS 推荐对上述命令添加 `--manual-proxy`，按提示仅设置 HTTP 代理；结束时先恢复原设置，再在终端按回车。
也可添加 `--network-service Wi-Fi` 尝试自动管理指定网络服务，但认证代理、原 HTTP 代理地址为空等无法完整恢复的配置会拒绝自动修改。
macOS 原生代理修改和真实微信收银台仍需实机验收；手动模式继续可用。

`check-cashier` 只验证微信页面加载官网模块、用真实用户接口校验并加密保存当前登录态、再接收结果，不创建订单或调起付款。
不依赖昨天保存的 Token；首个就绪请求验证成功后，后续领取严格绑定同一个登录态。

## 放号查询

在北京时间 19:45–20:03 内启动，先按上面的流程完成登录、阅读须知，然后运行：

```powershell
python -m projects.dachanbay_tennis release --approve-notice 实际SHA256 --unlimited-price --release-days 7
```

默认将当天加 7 天作为新放号日期，只匹配该日期的周二 21:00–22:00 或周三 19:00–20:00。
若场馆规则实际相差 8 天，改为 `--release-days 8`；日期是否开放和是否可预约仍以服务器为准。
其他日期已有空场不会混入本次放号下单。GUI 默认相差 7 天；可通过 `watch --release-days 8 --unlimited-price` 指定规则和价格。

微信接收页面在 19:45 起准备，**19:59:45 开始串行查询，20:03 结束**。
每轮日期/余量响应后间隔 0.1 秒；网络耗时会降低实际频率，不并发堆积请求。
只有发现匹配时段才执行完整复核，并且最多发送一次下单请求。
登录过期、服务器限流或其他请求异常会停止，未知结果不自动重试。
GUI 与命令行每日守候使用同一流程：本人在微信打开一次性页面，按官网提示完成必要授权，程序校验并保存当前登录态。
页面超过 90 秒没有心跳时停止下单；准备时限到期也会停止。请保持微信页面打开、网络稳定。
程序必须持续运行、电脑联网且不休眠。19:45 的应用提醒与实际预约进程分别运行，收到提醒不代表守候程序已启动。

无需图形界面的持续守候：

```powershell
python -u -m projects.dachanbay_tennis daily --approve-notice 实际SHA256 --unlimited-price --release-days 7
# 从另一终端请求停止，不中断已发出的下单请求：
python -m projects.dachanbay_tennis stop-daily
```

`daily` 仅在当天加 7 天为目标周二/周三时，于 19:45 准备一次性微信页面。
本人在电脑微信打开日志中的这一条链接，按官网提示完成必要的登录授权，然后保持页面打开。
程序校验并保存当前登录态，19:59:45 起查询目标日期并提交一次预约，直接在同一页交接收银台，无需再切换第二个链接。
其余日期直接等待下一次准备。页面准备超时或任何业务/网络异常会停止进程，需要检查原因后重新启动。
不会在登录失败或未知下单结果后继续重试。休眠、关机、退出进程会中断守候；不是系统开机服务。

## 登录与预约

1. 电脑微信登录场馆，访问 `http://spc.dachanbay.tencent.com/index`。
2. 点“启动本机代理”，记下 系统原代理设置，临时把手动代理设为 `127.0.0.1:8766`。
3. 微信重新进入网球预约页并切换日期，等待“登录凭证已加密保存”。无需安装证书。
4. **先恢复 系统原代理设置，再停止本机代理。**
5. 点“验证登录并查询”，阅读实时须知、设置单次价格上限（可填“不限”）并勾选同意，再选择立即预约或每日守候。

macOS 在“系统设置 → 网络 → 当前连接 → 详细信息 → 代理”中启用 HTTP 网页代理，设置服务器和端口并应用；结束前恢复原设置。
macOS 微信是否采用系统代理需实机核对；如未捕获请求，可使用窗口的本地 Token 输入，不要发送凭证给他人。

每日北京时间 19:59:45–20:03，每轮响应后间隔 0.1 秒查询，当天成功提交一次后等待次日。
保持程序运行、联网、电脑不休眠。实际可预约日期由接口决定，日期可见不代表资源已放出。
下单前复查余量、自己的订单、价格和数量限制，并调用资格检查；需要身份验证、验证码或额外确认时停止。
发送前持久化下单尝试，未知结果不重试，重启也保留记录。成功后由官网 SDK 交接微信收银台，本人核对并付款。
不自动支付、取消订单或伪造支付成功。不要同时运行仓库版和旧版输出目录中的程序。

## 本机数据

复用 `common.storage` 与 `common.concurrency`，默认目录：

```text
%LOCALAPPDATA%\book-ticket\dachanbay_tennis\
  credentials.dpapi       # 本机加密凭证（DPAPI / 钥匙串密钥 + Fernet）
  attempts.dpapi          # 加密的下单尝试记录
  proxy-recovery.dpapi    # 临时代理原设置，正常恢复后删除
  payment-trace-*.json    # 已脱敏支付诊断
```

macOS 默认目录为 `~/Library/Application Support/book-ticket/dachanbay_tennis`，文件名相同。
首次保存可能请求钥匙串授权，失败时停止；`.dpapi` 为兼容保留的文件名。

`BOOK_TICKET_DATA_DIR` 可更换数据根目录，项目名自动追加，与医院项目数据分开。
本次只迁入源码，没有复制旧版 `local_data` 或修改原运行实例。仓库版首次使用需要重新采集凭证；
开启前核对旧版预约记录，避免跨版本重复下单。不要通过删除尝试记录强行重试。
凭证、订单、诊断记录不提交到 Git。

## 一次性支付诊断

运行 `capture-payment`，或在 macOS 终端执行 `./projects/dachanbay_tennis/launch.command capture-payment`，Windows 也可双击 `capture-payment.cmd`，先停止预约任务及原代理。
开始采集后临时设置相同本机代理（macOS 需同时启用 HTTP 和 HTTPS，HTTPS 仍不解密），在电脑微信完成本人原本计划的付款，再返回订单详情。
先恢复 系统原设置，再结束采集。工具只转发本人请求，不创建订单或重放付款请求。

仅记录场馆支付相关 JSON 的脱敏结构、状态和金额；凭证、签名、openid 和个人信息不落盘，
订单号替换为本次采集内一致的匿名标识。正文最多 256 KiB、数组最多 2 个样本、总计最多 500 个事件。
HTTPS 仅转发，支付服务只记录域名、时间和流量大小，不解密收银台正文。
这些信息可用于研究场馆流程，不能证明可自动扣款，也不能确定支付风控原因。
