# 北京大学深圳医院 · 牙体牙髓科

范围：本人账号唯一可用就诊人，牙体牙髓科（补牙及根管治疗），任意医生、可预约日期和时段。医保或自费、费用上限及生物样本捐赠意愿由初始化时明确选择。仅预约，不自动付款、取消、候补或加号。

## 文件职责

- `core.py`：目标排班 HAR 导入、登录态保存和只读查询。
- `capture.py` / `assistant.py`：微信 HTTPS 本机采集及窗口。
- `api.py`：经核对的查询和校验接口、医院校验、错误分类。
- `configure.py`：读取当前告知并保存本机选择，不挂号。
- `booking.py`：分时、医保限制、告知、费用、重复预约校验和一次性提交。
- `site_crypto.py`：网站公开客户端的协议编码；这些协议常量不是个人账号凭证。
- `watch.py`：串行查询、退避恢复、状态日志和守候窗口。
- `config_fields.json`：网站公开配置的字段名称，不包含个人设置或登录态。

## 首次使用

在仓库根目录安装依赖后运行 `python -m projects.pkuszh capture`。

1. 窗口生成临时证书，核对名称、期限、指纹。点击安装后仍需确认当前 Windows 用户的临时根信任。
2. 记下原 Windows 代理，临时设置 `127.0.0.1:8767`。
3. 在电脑微信正常登录，进入牙体牙髓科并选择全部日期，无需挂号。
4. 显示已加密保存后，先恢复原代理，再结束采集并移除证书。
5. 运行 `python -m projects.pkuszh configure`，阅读当前告知并明确选择捐赠意愿、医保/自费和费用上限。
6. 运行 `python -m projects.pkuszh query` 验证只读查询，再用 `python -m projects.pkuszh watch` 打开守候窗口。

临时根信任是账户级变更。采集仅解析 `mp.mhealth100.com`，其他 HTTPS 原样透传；根签名私钥不保存，叶私钥临时受本用户 ACL 限制并在加载后删除。异常退出时需恢复代理，并在 `certmgr.msc` 按指纹移除该证书。到期不等于移除。

## 预约流程

排班展示分组和实际出诊科室编号不同，按目标名称匹配排班，再使用该条排班的实际科室编号。仅选择普通余号，并检查费用上限、分时、当前告知、服务对象、医保限制及已有挂号。

国家医保分支只有在实时医保状态、广东院区、网站相关医保配置和免验证预约配置满足时，才沿用排班公布的费用、优惠费用 0，使用网站的医保预约创建接口与 JSON 请求。其他分支仍要求费用查询成功，使用普通预约创建接口与网站规定的编码；费用失败不会默认通过。

捐赠告知内容变化、要求签名、人工验证、登录失效或资格限制时停止，不代选新增授权。

每次查询响应后等待 0.1 秒，单请求串行；网络耗时会降低实际频率。日志每分钟汇总查询轮数、排班数量及最近耗时。超时、断连和 HTTP 502/503/504 按 5、10、20、40、60 秒退避，之后每 60 秒检查；恢复后继续。医院业务错误和限流使用单独的有限重试规则；认证、TLS 或响应格式异常停止。

提交前加密写入订单日志，只发送一次。成功、明确拒绝或结果不明都停止，不重发未知结果。`registerMode=1` 表示网站锁号成功分支；`registerMode=0` 提示待支付。最终以微信挂号记录为准。

## 本机数据与测试边界

不复制他人的本机数据。运行数据默认保存在 `%LOCALAPPDATA%\book-ticket\pkuszh`，使用当前 Windows 用户 DPAPI 加密，不能跨 Windows 用户直接使用。状态日志只记医生、时间及错误类别。不要提交运行目录、HAR、证书、就诊人信息或账号凭证。

默认测试使用合成资料和离线协议向量。代码迁移后的真实医保状态读取、告知和下单全流程仍需有效登录态与真实余号验证；尚不声称真实挂号成功。
